# 0.2.0

## Added
* **Panic Unwind Safety:** Added `__DropGuard<T>` to the macro generation. If a user-provided iterator panics mid-write during initialization, any already-initialized slice elements are now safely dropped in place instead of leaking memory.
* **Massive Edge-Case Test Suite:** Added highly advanced integration tests in `tests/test.rs` to guarantee safety against zero-sized types (`()`), heavily aligned types (`#[repr(align(64))]`), lying iterators, and panic unwinds.
* **Architecture Documentation:** Authored a deep-dive `DESIGN.md` covering the memory layout math, the heap corruption bugs, and exactly how the View API solves disjoint borrowing.

## Breaking Changes
* **`view_mut()` Return Type:** The `.view_mut()` method has been completely redesigned. It now consumes the `Pin<&mut Self>` and returns a newly generated `[StructName]ViewMut` struct. Any previous code relying on the old return type will need to be updated to use this new transparent struct, which was introduced to solve partial/disjoint borrowing limitations.
* **Strict Iterator Panics:** The `new_box_iter` constructors are now strictly bounds-checked. If you pass an `ExactSizeIterator` that yields *fewer* elements than its `.len()` promises, the constructor will now **panic**. (In `0.1.x`, this silently caused Undefined Behavior).

## Changed
* **View API Redesign (Disjoint Borrowing):** Redesigned the `view_mut()` method to consume `Pin<&mut Self>` and return a generated `ViewMut` transparent struct. This explicitly inherits the visibilities of the original fields and allows the Rust borrow checker to track borrows to individual slices independently, solving the partial-borrowing limitation.
* **Documentation Overhaul:** Rewrote `README.md`, `src/lib.rs`, and the macro-generated docs to be more concise and user-friendly. Added missing `#[doc]` attributes and a mock API reference.

## Fixed
* **Heap Corruption (Alignment Mismatch):** Fixed a critical bug where `Box::dealloc` would crash with `STATUS_HEAP_CORRUPTION`. The bug occurred because the custom allocator used a large alignment (e.g., 64) for the tail, but the compiler inferred a smaller pointer-sized alignment for the sized prefix. Fixed by embedding zero-length arrays (`__align_N: [T; 0]`) into the sized prefix to force the compiler to recognize the maximum slice alignment statically.
* **Buffer Overflows (Lying Iterators):** `ExactSizeIterator` can no longer cause buffer overflows or uninitialized memory reads. The macro's `new_box_iter` initialization loops are now strictly bounded to the exact memory length allocated. If an iterator yields fewer items, the constructor uses `.expect()` to safely panic. If it yields more, the excess is ignored.
